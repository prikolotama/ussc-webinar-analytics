# Аналитика вебинаров ЦК УЦСБ

React + TypeScript + Vite. Импорт Excel, нормализация регистраций, связанные фильтры и диаграммы, аналитика должностей, матрицы пересечений, компании и локальный PDF. Обработка выполняется в браузере без бэкенда, ИИ и внешних аналитических API. Загруженные файлы не передаются в GitHub и не сохраняются между обновлениями страницы.

## Запуск

Требуется Node.js 22.12+ с npm.

```bash
npm install
npm run dev
npm test
npm run build
```

Vite напечатает локальный адрес. Production-сборка находится в `dist/`; открывайте её через HTTP-сервер, а не `file://`. Проверенные версии также зафиксированы в `pnpm-lock.yaml`, можно использовать pnpm.

## GitHub Pages

Репозиторий: https://github.com/prikolotama/ussc-webinar-analytics

Адрес сайта после включения Pages: https://prikolotama.github.io/ussc-webinar-analytics/

Готовая сборка находится в `docs/`. В **Settings → Pages → Build and deployment** выберите **Deploy from a branch**, ветку **main**, папку **/docs**, затем **Save**.

После изменения исходников обновите сборку:

```bash
npm test
npm run build:pages
```

Затем закоммитьте исходники и обновлённую папку `docs/`. Pages опубликует изменения после push. Команда `build:pages` заменяет только сгенерированную папку `docs/`, удаляя устаревшие хешированные ресурсы. Относительные пути поддерживают подпапку репозитория. `.nojekyll` отключает обработку файлов как Jekyll.

## Импорт Excel

Поддерживаются `.xlsx` и `.xls` до 30 МБ. Доступны drag-and-drop, выбор файла и деморежим с синтетическими данными. Пример структуры — `public/Пример регистраций.xlsx`.

Ожидаемые столбцы: «Коммерческое наименование», «Отрасль», «Город», «Должность гостя», «Источник». Порядок произвольный, лишние столбцы игнорируются. Заголовки ищутся в первых 30 строках. Автоматически выбирается лист с наибольшим числом распознанных полей.

При однозначном распознавании видны краткая сводка и кнопка «Построить аналитику». «Изменить сопоставление» раскрывает лист, номер строки заголовков и ручное сопоставление. Если поля не найдены, лист пуст или подходят несколько листов, настройки раскрываются автоматически. Отсутствующие поля можно оставить как «Нет столбца». Повторное сопоставление одного столбца нескольким полям запрещено.

Пустые по выбранным полям строки исключаются; неполные записи сохраняются с категорией «Не указано». Новый файл заменяет текущую выборку, фильтры и ручные настройки.

## Показатели и фильтры

- Одна непустая регистрационная строка = одна регистрация. Полностью совпадающие строки сохраняются и отмечаются предупреждением. Уникальных людей и фактическое посещение по этим данным определить нельзя.
- Компании считаются отдельно от регистраций. Неизвестные компании исключены из количества компаний и таблицы организаций.
- KPI городов, отраслей и источников считают известные категории. Диаграммы включают «Не указано», чтобы сохранять сумму регистраций.
- Проценты диаграмм рассчитаны от текущей выборки. В матрице процент рассчитан от всей строки, включая категории за пределами Top-N.
- Значения внутри одного фильтра связаны через ИЛИ, разные фильтры — через И. Нажатие на столбец, название должности или сектор применяет фильтр. Ячейка матрицы устанавливает сразу два фильтра. Чипы снимают отдельные ограничения, «Сбросить» очищает все.

Доступны абсолютные/процентные значения, сортировка, Top-5/10/20 и полный список с поиском и страницами по 25 категорий. Длинные должности переносятся полностью. Источники показаны кольцевой диаграммой с остатком «Остальные категории» при ограничении списка. Матрицы: отрасль × источник, отрасль × должность, должность × источник, город × источник, компания × должность. Полный режим матрицы имеет страницы по 15 строк и 10 столбцов.

Таблица компаний агрегирует регистрации, отрасли, города, должности и источники. Поддерживаются поиск, сортировка, страницы по 10 компаний и раскрытие распределений.

## Нормализация и должности

В «Настройка данных» / «Проверить данные» сохраняются исходные значения и редактируются итоговые категории. Одинаковое итоговое имя объединяет категории, разные имена разделяют их. Изменения сразу пересчитывают всю аналитику. Если переименование конфликтует с выбранным фильтром, сбросьте фильтры.

Словари распознают пробелы, регистр, кавычки, однозначные варианты городов, отраслей, источников и должностей: МСК, СПб, Нск, Екб, IT/ИТ, Email/E-mail, Telegram/TG, CISO/CIO, SOC и другие. Юридические формы компаний автоматически не удаляются; нечёткое объединение организаций не используется.

«Предложения объединений» позволяет проверить варианты брендов и юридических названий по отдельности. Укрупнение источников отдельно объединяет РСЯ/Яндекс.Директ в контекстную рекламу и партнёрскую рассылку с партнёрами. Без этого подробные источники сохраняются.

Должности переключаются между конкретными и взаимоисключающими группами. Редактируемые правила проверяются сверху вниз, применяется первое совпадение. При отсутствии совпадений — «Не определено». Общие «Инженер», «Специалист», «Начальник отдела» и неоднозначное PM не получают выдуманную специализацию.

Дополнительные показатели руководителей, ИБ-аудитории, разработчиков и проектного/продуктового менеджмента могут пересекаться. Разработчики определяются по явным названиям Developer/Software Engineer/Frontend/Backend/Full-stack, разработчика и программиста; QA, Business Development и Developer Relations исключены. Менеджмент включает явные проектные и продуктовые роли, Product Owner, CPO и Scrum Master. «Без должности» означает неизвестную должность, а не все роли вне классификации.

## PDF

Экспорт отражает текущие фильтры и включает название, логотип, KPI, отрасли, конкретные должности и группы, источники, географию, пять матриц Top-6, фильтры и статистические итоги. Длинные распределения разбиваются на страницы. Формирование полностью локальное и может занять несколько десятков секунд.

Кириллица сохраняется изображением: текст PDF не предназначен для выделения и поиска. PDF использует отдельное светлое оформление и Arial. Показатели и страницы проверены на демоданных; крупные файлы с множеством уникальных категорий увеличивают объём отчёта и потребление памяти.

## Приватность и ресурсы

Рабочие файлы остаются в памяти вкладки. Нет телеметрии, внешнего хранения, CDN-шрифтов и отправки данных на сервер. История, импорт и исправления сбрасываются при обновлении страницы. В `docs/` и репозиторий не включаются пользовательская проверочная книга и локальные скриншоты.

Onest с кириллицей хранится в `public/fonts/`, лицензия — `OFL-Onest.txt`. Референс оформления — https://sec.ussc.ru/. Логотип получен из официальных материалов: https://static.tildacdn.com/tild6636-3161-4136-b930-343734643031/logo_.svg. Палитра адаптирована по найденным на сайте цветам `#f7a71f`, `#141414`, `#202020`; это не утверждение о наличии брендбука. Основные токены находятся в `src/styles.css`.

## Структура и проверки

- `src/lib/excel.ts` — чтение и распознавание книги.
- `src/lib/normalization.ts` — словари и предложения объединений.
- `src/lib/analytics.ts` — нормализация, классификация, фильтры, KPI, распределения, матрицы, компании и резюме.
- `src/lib/pdf.ts` — локальный экспорт, библиотеки загружаются по запросу.
- `src/components/` — импорт, диаграммы, редактор, матрица и таблица.
- `src/App.tsx` — единое состояние и композиция интерфейса.
- `src/tests/` — вычисления, Excel, импорт и тематические показатели.

В открытом проекте выполняются 45 тестов. Ещё 7 проверок пользовательской книги включаются только при наличии локального `src/tests/fixtures/webinar-100.xlsx`; этот файл исключён из Git. Проверяются повторы, пропуски, проценты, матрицы, фильтры, 10 000 записей, XLS/XLSX, несколько листов и ошибки распознавания. Браузерная проверка включает импорт, длинные должности, новые показатели, фильтрацию, мобильную ширину и локальные ресурсы.
